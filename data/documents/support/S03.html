Authentication Troubleshooting

IT Support | Updated 1 September 2026

Triage the visible failure

Record the failed action and whether it happened before or after MFA. Use the code to choose the next step.

CodeMeaningFirst action
HTTP 401No valid authenticated sessionFollow Session recovery below
HTTP 403Signed in, but permission is missingCheck organization and ask HR to review the role
AUTH-423Temporary lockoutWait for the lockout to end
AUTH-DISABLEDAccount disabled by HRAsk HR to review; a password reset will not reactivate it

Do not clear cookies repeatedly before recording the failure.

Session recovery

  1. Save unsent text locally without copying confidential record contents.
  2. Sign out, close other PeopleFlow tabs, and reopen the approved workspace bookmark.
  3. Sign in once and verify the selected organization.
  4. Repeat the action on a nonsensitive record if possible.

If a new session resolves HTTP 401, the earlier session likely expired. Sessions expire after 30 minutes idle or 12 hours from sign-in. A recurring 401 immediately after sign-in may indicate blocked first-party cookies or a stale organizational login route. Use a supported browser and permit the organization's required first-party session cookies. Do not disable browser security globally.

MFA and lockout

Authenticator codes contain six digits and rotate every 30 seconds. Set automatic device time and use the next newly generated code once. Five failed password attempts within 15 minutes trigger a 30-minute lockout. Wait for the lockout to end rather than creating a series of reset requests. A password reset link lasts 20 minutes and is invalidated when a newer link is requested. AUTH-410 means the reset link has expired or been replaced.

Escalation and disabled accounts

Lost MFA enrollment requires HR identity verification before an administrator resets it. An AUTH-DISABLED account must be reviewed by HR; support cannot infer employment status or reverse deactivation. For persistent failures, submit browser and application versions, the error code, event time with timezone, and whether a fresh session worked. Never submit a password, MFA code, reset link, session cookie, or recovery secret. Support Escalation & Security Incidents applies if an unexpected authentication event suggests unauthorized access rather than an ordinary login failure.
